  Containers general characteristics
 

1. Most containers are evaluated for each request.

2. The enclosed directives are applied only for those requests that match the containers.

3. The <IfDefine>, <IfModule>, and <IfVersion> containers, on the other hand, are evaluated only at server startup and restart.
  <ifdefine>
 

1.The <IfDefine> directive encloses directives that will only be applied if an appropriate
parameter is defined on the httpd command line

2.For instance, all requests will be redirected to another site only if the server is started using httpd -DClosedForNow:


<IfDefine ClosedForNow>
Redirect / http://otherserver.
example.com/
</IfDefine>
  <ifmodule>
 

1. The module must either be statically compiled in the server, or it must be dynamically compiled and its LoadModule line must be earlier in the configuration file.

2. the MimeMagicFiles directive will be applied only if mod_mime_magic is available.


<IfModule mod_mime_magic.c>
MimeMagicFile conf/magic
</IfModule>
  <IfVersion>
 

1. it encloses directives that will only be applied if a particular version of the server is executing

<IfVersion >= 2.1>
# this happens only in versions greater or
# equal 2.1.0.
</IfVersion>
  Negative and nested
 

1.<IfDefine>, <IfModule>, and the <IfVersion> can apply negative conditions by preceding their test with "!".

2.They can be nested
  The difference between filesystem and webspace
 

1. The filesystem is the view of your disks as seen by your operating system

2. the webspace is the view of your site as delivered by the web server and seen by the client.

3 For instance, path /dir/ in the webspace corresponds to the path /usr/local/
apache2/htdocs/dir/ in the filesystem of a default Apache install on Unix.
  Filesystem container
 

1. Directives enclosed in a <Directory> section apply to the named filesystem directory and all subdirectories of that directory.

For instance, directory indexes will be enabled for the /var/web/dir1 directory and all subdirectories.

<Directory /var/web/dir1>
Configuration Sections - Apache HTTP Server
Options +Indexes
</Directory>

2. Directives enclosed in a <Files> section apply to any file with the specified name, regardless of what directory it lies in.

<Files private.html>
Order allow,deny
Deny from all
</Files>

3. the <Files> and <Directory> sections can be combined.

<Directory /var/web/dir1>
<Files private.html>
Order allow,deny
Deny from all
</Files>
</Directory>
  Webspace container
 

1. The <Location> directive change the configuration for content in the webspace.

For instance, the following configuration prevents access to any URL-path that begins in /private.

<Location /private>
Order Allow,Deny
Deny from all
</Location>

2. The <Location> directive need not have anything to do with the filesystem.
  Wildcards and Regular Expressions
 

1. "*" matches any sequence
of characters

2."?" matches any single character

3. "[seq]" matches any character in seq

4. "/" character will not be matched by any wildcard

For instance,

<FilesMatch \.(?i:gif|jpe?g|png)$>
Order allow,deny
Deny from all
</FilesMatch>
  When should we use filesystem or webspace?
 

1.When applying directives to objects that reside in the filesystem always use <Directory> or<Files>.

2. When applying directives to objects that do not reside in the filesystem (such as a
webpage generated from a database), use <Location>.

Pay Atte:It is important to never use <Location> when trying to restrict access to objects in the filesystem.
  Virtualhost
  1. Virtualhost is useful when serving multiple hosts from the same machine with a different configuration for each
  Proxy
 

1. The <Proxy> and <ProxyMatch> containers apply enclosed configuration directives only to sites accessed through mod_proxy's proxy server that match the specified URL.

2 For instance,

<Proxy http://cnn.com/*>
Order allow,deny
Deny from all
</Proxy>
  What Directives are Allowed?
 

1. The AllowOverride directive works only in <Directory> sections.


2. The FollowSymLinks and SymLinksIfOwnerMatch Options work only in <Directory> sections or . htaccess files.


3. The Options directive cannot be used in <Files> and <FilesMatch> sections.
  The order of sections merging
 

1. <Directory> (except regular expressions) and .htaccess done simultaneously (with .htaccess, if allowed, overriding <Directory>)


2. <DirectoryMatch> (and <Directory ~>)


3. <Files> and <FilesMatch> done simultaneously


4. <Location> and <LocationMatch> done simultaneously
